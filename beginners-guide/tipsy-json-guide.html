What is a world book?

A world book is a file of extra lore that Tipsy injects into the conversation — but only when it's needed. Instead of cramming every piece of world-building into the Background field, you keep it in a separate file and let trigger words pull it in on demand.

Think of it like a reference library sitting behind the chat. As long as nobody mentions dragons, the dragon lore isn't taking up space. The moment someone writes "dragon" in a message, that entry gets injected and the bot knows exactly what to do with it.

The file format is JSON — a plain text format with a specific structure. You don't need to know how to code to write one. You just need to understand the three fields every entry uses.

why bother with a world book? The Background field has a token limit. A detailed world with factions, locations, lore, and NPCs will blow past it fast. A world book keeps your Background lean and only adds detail when the conversation actually needs it.
the format ❤

The structure

The whole file is one JSON object containing one array called entries. Each item in that array is one lorebook entry with exactly three fields.

❤ the full file shape
// the whole file is just this: { "entries": [ { "keys": ["trigger word", "variant", "alt phrasing"], "content": "The lore text that gets injected when a key matches.", "enabled": true }, { "keys": ["another trigger", "variant"], "content": "A second entry with its own lore.", "enabled": true } ] }
JSON is picky about punctuation Every entry needs a comma after it except the last one. Every string needs to be in double quotes. One missing bracket or rogue comma and the whole file breaks. If your world book isn't loading, that's almost certainly why — check your commas and brackets first.
the three fields ❤

Keys, content, enabled

Every entry has exactly these three fields. No more, no less.

keys What triggers this entry
An array of trigger strings. When any key appears in a message — from either the user or the bot — this entry's content gets injected into context. Include the canonical name plus common variants, abbreviations, and the way a real person might actually type it.
"keys": ["The Iron Throne", "Iron Throne", "throne", "the throne"]

Keys are not case sensitive — write them as they'd naturally appear in conversation. Aim for 4–8 keys per entry covering the formal name, short forms, and how a roleplayer might actually phrase it.

content The lore that gets injected
The actual text that gets added to context when this entry fires. One dense paragraph is the target — roughly 60–150 words. Enough to establish tone, key facts, and a hook for the bot to work with. More than that and you're burning token budget on detail the scene may never need.

Write in third person, present tense for standing facts. End with something unresolved — a tension, an open secret, an ironic detail — so the bot has something to play with rather than just a list of dry facts.

enabled On/off switch
A simple true/false toggle. Set to true to include the entry, false to exclude it without deleting it from the file. Useful for entries you want to keep around but switch off for a specific story arc.
"enabled": true // active — will fire when keys match "enabled": false // inactive — kept but ignored
writing good entries ❤

How to write entries that work

The structure is easy. The craft is in the content. Here's what separates world book entries that actually help the bot from ones that just take up space.

❤ End on a hook, not a full stop

Dry facts give the bot nothing to do. An unresolved tension, an open secret, or an ironic detail gives it something to play with. "The council is unified in public and fractured in private — the question is which fracture will split first" is more useful than a list of council members' names.

❤ Cross-reference other entries by name

If your "Iron Order" entry mentions the "Splinter Sect" in passing, and your "Splinter Sect" entry mentions the "Iron Order," then triggering either one nudges the bot toward a consistent picture of both — even if only one fired. Entries that know about each other behave like a real world.

❤ Cover how people actually talk

Your keys should include both the formal name and the casual shorthand. If your faction is called "The Brotherhood of the Eternal Flame," someone in chat is going to type "the Brotherhood" or just "the flame guys." Cover both or the entry won't fire when it should.

❤ Keep content to one paragraph

60–150 words. Every entry that fires is eating into the token budget for the actual conversation. A wall of lore that fires on a common word can quietly throttle the quality of everything else. Dense and specific beats long and comprehensive.

test your triggers After uploading your world book, have a conversation that deliberately uses your key words and check whether the bot's responses shift. If an entry isn't firing, the key probably doesn't match how people are actually writing — add more variants.
worked example ❤

A complete world book entry

Here's what a finished entry looks like for a fantasy faction — keys, content with a hook, enabled. This is the pattern to copy.

❤ complete entry — fantasy faction example
{ "keys": [ "The Iron Order", "Iron Order", "the Order", "Iron Knights", "the knights" ], "content": "The Iron Order is a centuries-old military brotherhood sworn to protect the capital from threats the crown refuses to acknowledge. They answer to no monarch and fund themselves through tribute from the merchant class, which has made them both indispensable and deeply resented. Their ranks are drawn exclusively from second sons — men with inheritance enough to be trained but not enough to be missed. Within the Order, loyalty is absolute and silence is law. What the senior brothers know about the current king's debts to them has never been said aloud, which is precisely why everyone is afraid of it.", "enabled": true }
notice the hook The entry ends on an unresolved tension — what the Order knows about the king's debts, and why nobody says it aloud. The bot now has something to play with every time the Iron Order comes up, without being told exactly what to do with it.
❤ two entries in a complete file
{ "entries": [ { "keys": ["The Iron Order", "Iron Order", "the Order"], "content": "The Iron Order is a centuries-old military brotherhood... [entry text]", "enabled": true }, { "keys": ["Splinter Sect", "the Sect", "heretics"], "content": "The Splinter Sect broke from the Iron Order forty years ago... [entry text]", "enabled": true } ] } // note: comma after first entry, NO comma after last entry
before you upload ❤

Common mistakes

These are the things that silently break a world book. Check for them before you upload.

❤ Missing or extra commas

Every entry needs a comma after its closing } except the last one. Same for keys — every key string needs a comma after it except the last. This is the most common reason a world book fails to load.

❤ Single quotes instead of double quotes

JSON requires double quotes "like this" for all strings. Single quotes 'like this' will break the file. If you're writing your entries in a word processor, watch out for "smart quotes" curling the wrong way — use a plain text editor instead.

❤ Keys that are too generic

A key like "he" or "the" will fire on almost every single message and inject lore constantly. Keep keys specific enough that they only fire when the topic is actually relevant.

❤ Content that's too long

There's no hard character limit on content, but every word that fires is a word the model can't use for the actual conversation. If an entry is over 200 words, split it into two entries with different trigger keys.

validate your JSON before uploading Paste your file into a free JSON validator (jsonlint.com is good) before uploading to Tipsy. It'll show you exactly where any syntax errors are. Saves a lot of guessing.
